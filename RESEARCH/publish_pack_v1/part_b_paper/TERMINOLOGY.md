# Reader glossary (avoid internal lab slang)

Use these forms in Part B prose. Condition codes (A1/A2/A3, B1/B2) are fine once defined.

| Internal / lab | Prefer in the paper |
|----------------|---------------------|
| ticket | **exam case** (or **case**) |
| full ticket success | **end-to-end success** / **full case pass** |
| ticket-level / ticket-averaged | **case-level** / **case-averaged** |
| Axis A | **prompt-style** conditions (A1–A3); primary contrasts |
| Axis B | **run mode** (instant vs thinking; B1/B2) |
| task scaffold | **task instructions** / **instruction stack** |
| claim bar / clear the bar | **pre-set statistical threshold** / **excludes zero** |
| reading plan | **analysis plan** (locked before the confirmatory runs) |
| Track 1 | **this confirmatory study** (or name once, then “this study”) |
| scored runs | **graded attempts** |
| pureLong / `S_role_long_pure` | **longer pure persona** (code OK in tables) |

Do **not** invent a second meaning for “ticket” (support ticket) without saying so — outsiders will think of helpdesk tickets.
